# Reversible retention of expanded dev test trees

`tools/archive_retained_source.py` retains older expanded test-preservation trees when they prevent the existing dev worker from meeting its free-space gate. This is local evidence retention, not a new worker layout, an S3 replacement or a change to official release archives. The tool performs no uploads and never selects a tree automatically.

Execution requires `tomcata` on `ncias-d3777-c`, the existing `/local/content/MEME/MEME5/inv` layout, and the existing exclusive `.replay-runtime.lock`. Active common-worker stages therefore exclude archive, verification, retirement and restore operations. There is no CLI guard bypass. Targets must be direct real children of `sources`, named one of the five reviewed versions followed by `.before-<identity>`: NCI_2026_10D, SNOMEDCT_US_2026_09_01, MTH_2026AA, MDR_29_1 or RADLEX_4_3. Current canonical folders, `.tgz` files, unknown versions, symlink roots/ancestors and nested targets are rejected.

Use separate explicit steps:

1. `archive --source <absolute retained-tree path> --destination <ROOT>/qa/retained-source-archives/<new unique identity>` creates `tree.tar.gz`, `manifest.json` and `archive-receipt.json` in a fresh namespace. It does not retire the expanded tree.
2. Retain the returned receipt SHA-256 separately with the run evidence. Review the expanded regular-byte total, regular-file count, compressed size and full verification. `verify --archive <archive> --receipt <receipt> --receipt-sha256 <returned hash>` independently reopens the whole archive.
3. Only then use `retire --source <same expanded path> --archive <archive> --receipt <receipt> --receipt-sha256 <returned hash>`. This independently verifies the pinned receipt, archive hash and every member, compares the complete live tree to the original capture, rechecks evidence hashes, and durably flushes the backup before removing any expanded entry.
4. `restore --archive <archive> --receipt <receipt> --receipt-sha256 <returned hash> --destination <absent allowed retained-tree path>` restores the original version into a fresh retained name. It refuses to overwrite an existing path. No `extractall` call is used.

The equivalent Python functions are `archive(source, destination, retire=False)`, `verify(archive, receipt, expected_receipt_sha256)`, `retire(source, archive, receipt, expected_receipt_sha256)` and `restore(archive, receipt, destination, expected_receipt_sha256)`. The CLI deliberately offers retirement as a separate command.

The manifest records root mode/mtime and every relative path, type, mode and nanosecond mtime. Files record byte counts and SHA-256; symlinks record their target without following it. The gzip stream uses fixed compression level 1, and PAX headers retain modification times. Verification reads and hashes every regular tar member, and compares every directory, link, mode and mtime. Empty directories and broken/external symlinks survive round trips. Hardlinks and special files are rejected because this contract does not preserve their topology. Ownership, ACLs, extended attributes, atime and ctime are outside this file/mode/topology contract.

Source capture uses no-follow directory/file descriptors and rejects mutations of content, identity, modes, mtimes or topology. Reading-induced atime changes and ctime-only changes do not invalidate unchanged content. Retirement temporarily adds owner permissions only to captured directories, removes entries through no-follow directory descriptors, and uses ordinary unlink/rmdir operations; a newly added unarchived file prevents its parent from being removed. Archive/manifest/receipt files remain read-only and are never removed by this tool. Files, namespace and parent directory are fsynced; failed durability checks abort retirement.

If capture fails, its unique namespace and any partial archive remain for inspection; a failed attempt is never overwritten. If retirement is interrupted, the original verified archive and receipt remain intact, operation receipts describe the partial state, and surviving directory modes are restored where possible. Recovery is to restore **beside** the partial tree under another fresh allowed `.before-` name, verify that restored tree, and inspect any partial/newer data separately. Never overwrite a partial or newer tree. A restored tree has new inode identities and needs a new archive/receipt before another retirement.

The receipt's archive hash and externally retained receipt hash bind the precise backup. They are not a substitute for the per-member checks. The tool does not automatically delete incomplete namespaces or retained archives. Both the compressed archive and expanded tree coexist until verification and explicit retirement complete. Compression enforces a fixed **8 GiB free-disk reserve**, checked before the first compressed write and at least once per MiB of compressed output. Checks retain an additional write interval of headroom. There is no CLI override. Falling below the reserve aborts capture, retains the partial archive namespace and leaves the expanded source unchanged; no verified receipt is issued.

`python3 -B tools/check_archive_retained_source.py` exercises local temporary trees, without server access. Fixtures cover exact round trips, historical nanosecond mtimes, external/broken links, empty/read-only directories, source/ancestor guards, canonical-folder rejection, namespace and restore collisions, full content corruption, receipt/manifest tampering, mutation during/after capture, partial retirement recovery, durability failures, hardlinks/special files and runtime-lock exclusivity. Passing fixtures are not evidence that a real server tree has been archived; each actual operation retains its own receipt.
