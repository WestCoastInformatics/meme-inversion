# NCIt configuration generation

The first generator case uses the verified October 2026 inputs and explicit August replacement. Local property, plan-binding and real Perl fixtures pass; a fresh full common replay is the remaining integration gate. Production remains unchanged.

## Code, policy and release data

`engines/nci` is the release-independent Git package. Its [provenance](../../engines/nci/provenance.json) ties the four executed scripts to the verified `bfda2ce` producer. Core inversion and TREF deduplication retain identical bytes. The two preparation scripts accept declared filenames as arguments and reject absent arguments; they have no dated fallback. Historical snapshots and unused wrappers stay in the baseline history.

The [property template](../../engines/nci/nci.cfg.in) retains every effective property, including existing spelling/casing and representation rules. Comments/formatting are presentation changes. This stage does not silently fix or reinterpret policy. Common configuration supplies release values; explicit artifact references supply native exports, saved metadata, range evidence and the external hierarchy root.

| Common field | Generated/verified behavior |
|---|---|
| `version` | `VSAB`, subsource VSAB values and versioned RSSN property keys |
| `engine_ref` | Four code files loaded from the canonical Git package at the immutable commit |
| `policy_ref` | Exact Git template identity and unchanged representation policy |
| `inputs.source_data` | Five unique publisher roles mapped to exact hash-identified export filenames; the export date is not derived from the release month |
| `inputs.reference_ncimeta` | Saved `sources.src` and `termgroups.src`, restored as declared inputs |
| `inputs.identity_state` | Explicit saved root ID; root code/name must agree with the selected policy |
| `replacement_baseline` | Checked against the current source row in the saved metadata before publishing/preparing the candidate; October can replace August |
| `source_atom_ids.start` | Native `SaidStart` |
| `source_atom_ids.end`, `bound_kind`, `provenance_ref` | Complete outer validation bounds and provenance; an observed historical span is not relabeled as a production reservation |
| `comparison_baseline`, `publisher_history` | Explicit null/empty in this core profile; additional change-detection/history stages require a reviewed profile |

The rendered compatibility file stays at the standard release `etc/nci.cfg` path and is read-only. Git supplies executables; S3 supplies declared data. No prior release executable folder is consulted or copied. Existing data folders and earlier dev runs are preserved through the same common lifecycle.

## Run and preview

Use [the reviewed request](request-examples/nci-generated-configuration.json) with the ordinary seven common fields. Resolve/submission/status/collection are unchanged:

```sh
python3 -B tools/inversion_request.py resolve docs/inversion-review/request-examples/nci-generated-configuration.json --run-id nci-generated-001 --output generated.lock.json
python3 -B tools/nci_configuration.py generated.lock.json --output-dir rendered-preview
```

The optional local preview writes the configuration and its binding receipt to a new directory; it does not stage server data or run an inversion. Normal submission automatically stages the same generated bytes and passes the resolved filenames to native preparation. Use the [common lifecycle commands](common-interface.md#dev-lifecycle), including predecessor inspection and explicit runtime activation. Existing run IDs and preview directories cannot be overwritten.

The lock includes separate source-code and generated-setting provenance, the pinned template bytes, exact generated-file hashes and native preparation arguments. Recomputed recipes must agree with the common configuration, artifact identities and legacy preparation contract. Missing/changed recipes, substituted package paths, mismatched saved metadata, writable/changed settings and changed outputs reject the run. Inputs, generated settings and code are verified again after execution.

## Validation boundary

The independent golden check compares every effective October property with the captured verified configuration. Real Perl fixtures use different dated filenames and verify exact TREF/role-group serialization. A synthetic later plan renders different source/subsource versions and a skipped-month baseline without changing code; it is not an executed or approved future release.

This delivers the NCIt generator and a bounded October compatibility case. Only reviewed historical source/version cases can execute through the common interface. New-release metadata acquisition, source/subsource policy decisions, production allocation/eligibility, legacy QA/insertion, and configuration generators for the other sources remain separate work. Standard server paths are retained.
