# SNOMEDCT_US native engine

This package starts from the verified meme-edit capture `3b125edc1d29f7c7a91673da2a8d752bb0adff44`; [provenance](provenance.json) records the original paths and hashes. The cleanup script is unchanged. The converter changes only three hardcoded ICD target-year expressions into required compatibility properties. Their captured values remain valid explicit policy inputs; another release's mapping targets must be supported by its archived producer or reviewed publisher evidence, never inferred from the SNOMED publication date.

`sct.cfg.in` preserves the captured representation rules while parameterizing the current source, inserted predecessor, source title, complete ID range and every consumed RF2 file path. `execute_release_snomed.build_plan(...)` consumes the common manifest and canonical template bytes; it does not consume an already-rendered target cfg. Preserved source/termgroup metadata and ICD inventories remain legitimate frozen inputs. Their deterministic row rendering is verified against their actual saved bytes, without creating a second metadata copy or calling a database.

Before the fixed native stages run, the source validator scans actual RF2 headers and records, source/description identities, effective dates, modules/dependencies, description types, relationship/association label mappings, ATNs, refset patterns and map correlations. Unreviewed values or changes to the captured mapping behavior block execution. Full/Delta, live MRDOC generation and new semantic exclusion policies are outside this profile.

The independent output validator uses the selected release and its declared inclusive bounds, retaining every identifier, qualifier, relationship group and duplicate. The first acceptance profile compares complete bytes exactly to the independently verified official inversion-stage reference. Insertion-enriched attributes are not an inversion reference. Source structural validation is not complete domain validation or production insertion approval.
